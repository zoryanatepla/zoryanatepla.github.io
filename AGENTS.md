# Робота над сайтом

- Використовуйте наявний checkout; не створюйте Git worktree без прямого прохання користувача.
- Редагуйте компоненти в `src/`, зображення в `public/`. Файли публікації в корені генеруються командою `npm run prepare:pages`; не редагуйте їх вручну.
- Побажання власника: після завершених змін сайту самостійно перевіряйте, комітьте й публікуйте зміни в `main` репозиторію `zoryanatepla/zoryanatepla.github.io`, без повторного запиту дозволу, якщо поточна задача не обмежує публікацію. Не перезаписуйте чужі зміни й не використовуйте force push.
- До публікації виконайте потрібні тести, `npm run prepare:pages` та релевантні `npm run test:pages`. Зафіксуйте вихідний код і згенеровані HTML/CSS/JS/зображення разом. Зберігайте попередні хешовані ресурси для кешованих сторінок.
- GitHub Pages налаштований на `main` → корінь. Після push перевірте завершення deployment або отримання оновленого HTML і ресурсів на публічному сайті. Не називайте успішний push підтвердженням завершеного deployment.
- Після успішної публікації фінальна відповідь — лише посилання на сайт: https://zoryanatepla.github.io/dentist/ (можна з `?v=<короткий SHA>`). Якщо публікація або перевірка заблокована, коротко повідомте фактичний стан і перешкоду.
- Не надсилайте справжні тестові заявки через Telegram чи інші зовнішні сервіси. Перевіряйте попередній перегляд, копіювання та правильність адреси й тексту Telegram-посилання без фактичного надсилання повідомлень.

- Після відкату міграції робочий сайт знову використовує `/dentist/`. У репозиторії `zoryanatepla.github.io` повна збірка зберігається в каталозі `dentist/`; коренева сторінка переспрямовує туди. Не видаляйте цей каталог і не міняйте base path без окремого запиту власника та перевірки завантаження CSS, JS і фото на публічному хостингу. Успіх GitHub Actions сам по собі не доводить справність зовнішніх ресурсів.
