# Зоряна Тепла — персональний сайт ортодонта

Двомовний українсько-англійський сайт на React 19, TypeScript, Vite, Tailwind CSS 4, Motion та Lucide. Головна, чотири окремі сторінки послуг, інтерактивна сторінка «Ваш шлях до посмішки», сторінка «Менторство», політика конфіденційності й 404. Під час збірки сторінки перетворюються на статичний HTML: основний контент доступний пошуковикам і без JavaScript.

## Локальний запуск

Потрібен Node.js 22.12+ або 24 LTS та npm.

```sh
npm ci
npm run dev
```

```sh
npm run check
npm run build
npm run verify:static
npm run preview
npm test
npm run prepare:pages
npm run test:pages
```

`npm test` запускає Playwright на production-збірці: перевіряє валідацію, Telegram-попередній перегляд, копіювання, фокус, мобільне кадрування та відсутність автоматичного надсилання. Реальні заявки не надсилаються. Тестам потрібен Chromium; у цій середовищі він є в `/usr/bin/chromium`. Для іншого шляху встановіть `CHROMIUM_PATH`.

## Оновлення V4: менторство та рух

`/mentorstvo/` — окрема сторінка можливого професійного менторства з описом аудиторії, п’яти напрямів і чотирьох орієнтовних кроків. Формат, доступність і вартість потребують погодження; сторінка не заявляє про діючі курси. Кнопка запиту відкриває Instagram лікаря. Англійська версія доступна за `/en/mentorstvo/`. Обидві адреси пререндеряться, мають власні метадані, canonical, hreflang і записи в sitemap.

`src/Mentorship.tsx` містить сторінку, `src/premium.css` — її адаптивні стилі, палітру та додаткові деталі руху. Перемикання теми триває 800 мс: кольори поверхонь, тексту, рамок і тіней переходять одночасно; зареєстровані кольори градієнтів інтерполюються на кореневому елементі. Іконки сонця й місяця змінюються без заміни DOM. Тема застосовується до першого відображення навіть за недоступного localStorage, а явний вибір синхронізується між відкритими вкладками.

Анімація починається з першого екрана «Ваша посмішка. Моя професійна турбота.». CSS запускає послідовність ще до гідратації: заголовок за словами, опис, кнопки, портретна композиція й промальовування лінії усмішки. Один IntersectionObserver на поточну сцену анімує окремі заголовки й абзаци та цілі картки, зображення з рамками, форму з полями, карту й інформаційні панелі. Для візуальних поверхонь observer стежить за нерухомою обгорткою, а всередині рухається весь блок; його текст повторно не зміщується. Фокус усередині форми негайно показує її повністю та зберігає введені дані. Поява помітна: прозорість від 8–12% до повної, поява слів заголовка зі зміщенням 28 px, тривалість 1300–1450 мс та короткий stagger слів. Текст не обрізається масками й не розмивається. Після повного виходу за viewport елементи знову готові до появи; повернення до розділу або до першого екрана відтворює анімацію. Швидка прокрутка не вимикає входи, а незавершені ефекти поза екраном скасовуються. Рух контейнера не накладається на рух його тексту. Фокус одразу розкриває інтерактивний елемент, `prefers-reduced-motion` показує вміст без руху. Нативне прокручування не перехоплюється, нумерація не повертається. Переходи сцен: вихід 380 мс, поява 720 мс.

На пристроях із мишею картки послуг при наведенні піднімаються на 18 px, збільшуються до 103,5%, а зображення всередині — до 110%. Перехід триває 1–1,4 с; кнопки, посилання та круглі елементи також мають помітні hover-стани. Використовуються окремі CSS-властивості `translate` і `scale`, тому ефект не замінює scroll-анімацію `transform`. На сенсорних пристроях і за reduced motion ці hover-рухи вимкнені. Карта має висоту за вмістом; плашку з цитатою поверх ілюстрації підходу прибрано.

Оновлення головної сторінки браузером повертає до першого екрана й прибирає `#about`, `#services` або інший якір. Мова та query-параметри зберігаються. Початкові прямі посилання на розділи, звичайна навігація, Back/Forward і перезавантаження окремих сторінок послуг залишаються доступними. Скидання виконується раннім скриптом до гідратації.

Додаткові сценарії `tests/premium.spec.ts` перевіряють нову сторінку, заміни зі скриншотів, проміжні кольори під час зміни теми, швидкі перемикання, синхронізацію вкладок, клавіатурне меню, доступність, екрани 320–1440 px та роботу без JavaScript. Запускайте `npm test` після звичайної root-збірки, а `npm run test:pages` після `npm run prepare:pages`; це різні base URL. Для одночасного запуску використовуйте окремі каталоги `--output`, щоб Playwright не видаляв артефакти іншого набору.

- `src/refinements.css` — насиченіша зелено-золота палітра, деталі поверхонь, нові картки та адаптивні стилі оновлення.
- `src/data/journey.ts`, `src/Journey.tsx` — тексти шести етапів, інтерактивна шкала, вкладки з клавіатурним керуванням.

- `src/motion/AnimatedHeading.tsx` — React-розмітка слів для H1–H4 без обмеження видимості літер; входом керує спільний observer. Семантичні заголовки та тексти доступні одразу, включно з SSR і режимом без JavaScript; imperative innerHTML не використовується.
- `src/motion/usePanelTransition.ts` — вихід/поява деталей лікування з обробкою швидких повторних натискань; останній вибір має пріоритет.
- `src/motion.css` — спільні мікровзаємодії, м’які світлові фони, лінії, timeline та вимкнення руху за системним налаштуванням.
- `.env.example` — публічні параметри збірки. Скопіюйте до `.env.local` для локальних налаштувань.

## Статичний хостинг і SEO

### Публікація цього проєкту на GitHub Pages

Робоча адреса після відкату: `https://zoryanatepla.github.io/dentist/`. Сайт безкоштовно розміщується в публічному репозиторії `zoryanatepla/zoryanatepla.github.io`, GitHub Pages: main → корінь. Купівля домену не потрібна.

`npm run prepare:pages` збирає попередню робочу версію з base `/dentist/` у `dist/`, перевіряє її й копіює повну збірку в каталог `dentist/`. Коренева головна сторінка й адреси короткочасної root-версії перенаправляють у `/dentist/`. Редагуйте `src/` і `public/`, а згенеровані файли публікуйте разом із вихідним кодом. Не видаляйте старі хешовані ресурси.

### Причина першого білого екрана та захист від повторення

Перша публікація коміту `7db0bb2` містила порожній вихідний HTML із `<script src="/src/main.tsx">`: GitHub Pages не компілює TypeScript. Браузер не міг запустити цей модуль, а порожній `root` не мав контенту. Після повторного відкриття можна було отримати вже новий HTML; стара відповідь могла затриматися в кеші браузера або CDN. Факт потрапляння вихідного HTML підтверджений Git-історією; конкретний стан кешу пристрою користувача недоступний.

Тепер шаблон лежить тільки в `src/index.html`, а до кореня публікації копіюється попередньо відрендерений HTML. `prepare:pages` перевіряє збірку **до** копіювання й перевіряє кореневі файли **після** нього: наявність реального `main`, зібраних JS/CSS, файлів ресурсів і правильних шляхів `/dentist/`; вихідні `.tsx`/`.ts` та нерозв’язані `%BASE_URL%` заборонені. Попередні файли з хешами в `assets/` зберігаються, щоб старий HTML і відкриті вкладки залишалися працездатними. Не видаляйте їх одночасно з випуском нового HTML.

Окремо виправлено `basename` браузерного й серверного роутерів: кінцевий слеш `/dentist/` тепер зберігається. Посилання запису ведуть на `/dentist/#appointment`, а не `/dentist#appointment`, що усуває зайвий редирект GitHub при перезавантаженні. Обидва варіанти навігації та повторне завантаження перевіряються тестами.

`npm run test:pages` тестує **саме корінь, який завантажується на GitHub**, через звичайний статичний сервер під `/dentist/`, без Vite SPA fallback. Перевіряються перше відкриття, перезавантаження, нова вкладка, прямі вкладені URL, варіант без кінцевого слеша, робота без JavaScript/за збою JS, кешований HTML попереднього випуску, нова сторінка та відхилення початкового незбираного шаблону. GitHub Pages може кешувати HTML; для перевірки щойно опублікованої версії можна відкрити адресу з параметром версії, наприклад `?v=2`. Це не замінює правильну збірку.

Фактичний стан публікації видно у GitHub Actions → **pages build and deployment**. Успішне завантаження Git-коміту саме по собі ще не підтверджує завершення публікації.

`npm run build` лише створює папку `dist/`. `npm run prepare:pages` готує файли для вже налаштованого GitHub Pages; після завантаження цих файлів у `main` GitHub запускає публікацію.

Для власного домену використовуйте `VITE_BASE_PATH=/`, а `VITE_SITE_URL` має бути **реальним HTTPS origin без шляху**. Для GitHub Pages проєкту задайте `VITE_BASE_PATH=/dentist/` і origin вашого GitHub Pages у `VITE_SITE_URL`. Значення мають бути встановлені **під час збірки**. Не розміщуйте стару root-збірку в підкаталозі.

```sh
# Після встановлення реальних значень у .env.local:
npm run build
```

Збірка створює `index.html` для кожної адреси, `404.html` і `robots.txt`. З `VITE_SITE_URL` додатково створюються **валідна абсолютна sitemap.xml**, canonical та абсолютні Open Graph URL. Без реального домену вони навмисно не підміняються вигаданою адресою; збірка виводить попередження. Команда `build:pages` задає для цього проєкту origin `https://zoryanatepla.github.io` і шлях `/dentist/`. Власний домен можна налаштувати пізніше.

Google Search Console: додайте реальний сайт, використайте DNS-перевірку або `VITE_GOOGLE_SITE_VERIFICATION` для HTML-токена та перебудуйте сайт. Після публікації подайте `${VITE_SITE_URL}${VITE_BASE_PATH}sitemap.xml` через кабінет Search Console. Сам факт наявності метаданих не означає індексацію чи підтвердження Search Console.

Schema.org використовує тільки надані замовником відомості про лікаря та асоціації. Немає вигаданих адрес, рейтингів, дипломів або нагород. Перед публічним запуском підтвердьте актуальність професійних фактів.

Українські адреси збережено; англійські мають префікс `/en/`. Усі вісім сторінок кожної мови та дві сторінки 404 пререндеряться. Перемикач мови зберігає сторінку й URL-фрагмент, внутрішні посилання зберігають мову. `src/i18n/en.json` містить переклад контенту, форми, помилок та доступних підписів. `src/lib/locale.ts` і `src/i18n/I18n.tsx` керують адресами та локалізацією. Для кожної сторінки є власні `lang`, title, description, canonical, Open Graph, `hreflang` uk/en/x-default і запис у sitemap.

`tests/preferences.spec.ts` перевіряє контакти, адресу карти, видалення позначених елементів, англійські прямі URL й перезавантаження, перемикання мов, помилки форми, тему між вкладками, роботу без JavaScript/сховища, адаптивність та автоматизовану WCAG AA перевірку. У UI-тестах `tests/fixtures.ts` підміняє лише зовнішній Google iframe, оскільки Google недоступний за мережевою політикою хмарної тестової машини. Перевіряються справжня embed-адреса й адреса посилання; це не перевірка доступності зовнішніх серверів Google.

## Перевірки

### Єдина motion-система

`AnimatePresence` утримує попередню сторінку до завершення виходу; `Routes` отримує її зафіксовану location. Новий вміст з’являється після виходу. Шапка залишається тим самим DOM-вузлом. Активний пункт за URL-фрагментом визначається після гідратації, тому прямі посилання `#services` та `#appointment` не спричиняють розбіжності статичного HTML і React. Немає overlay, блокування pointer-events або штучного завантажувача: повторне натискання під час переходу працює, а останній маршрут перемагає. Під час зміни розділу в межах сторінки використовується природний smooth scroll без перехоплення колеса/жестів і без перезапуску форми.

Метадані, фокус і прокручування оновлюються після монтування потрібної сцени. Повернення/перехід уперед анімуються та відновлюють збережену позицію читання. `DetailMotion` має один IntersectionObserver на поточну сцену; кожен вузол розкривається один раз. Постійні елементи підвала не перезапускаються при кожній навігації. Текст залишається в HTML і ніколи не очікує JavaScript, щоб стати видимим.

Рух переважно використовує transform/opacity. Blur 0,8 px застосовано тільки до окремих слів великих заголовків під час короткої появи; великі рухомі фони не мають blur/backdrop-filter. Декоративні градієнти повільно переміщуються окремими шарами. Для `prefers-reduced-motion` рух вимикається також під час активного переходу: Web Animations скасовуються, слова й фотографії стають статичними, сторінка й деталі перемикаються одразу.

Шість додаткових тестів `tests/motion.spec.ts` перевіряють порядок виходу/появи покадрово, відсутність порожніх кадрів, незмінність шапки, швидкі повторні переходи, Back/Forward і точну позицію на момент натискання, зміну етапів, scroll timeline, перемикання reduced motion під час анімації та типографіку всіх семи сторінок на 320/768/1440 px. Разом із базовими сценаріями — 24 браузерні тести.

Playwright перевіряє переходи й статичний HTML послуг, FAQ, клавіатурне порівняння, справжні контактні посилання, валідацію форми, відсутність надсилання без endpoint, сценарії успіху/помилки/непідтвердженого приймання/429/збою мережі з mock-відповідями, honeypot, відсутність горизонтального переповнення на 320–1920 px, мобільне меню, reduced motion та роботу без JavaScript. Axe перевіряє доступність головної, мобільної форми, послуги та політики.

Це автоматизовані перевірки, а не підтвердження доставки реальних заявок, медичного змісту, індексації Google чи польових Core Web Vitals. Справжні LCP/INP/CLS слід оцінити після розміщення на цільовому хостингу й накопичення даних.

Оновлення від 4 листопада 2026 року перевірене 18 браузерними тестами: 12 для наявного функціоналу та 6 для реального дерева публікації, нової сторінки й регресій. Зображення предметів тепер мають native lazy loading (герой послуги та нової сторінки завантажується одразу), ключові кириличні шрифти — preload. Локальний мобільний Lighthouse 13 на статичній HTTP-збірці з gzip: Performance 91, Accessibility 100, Best Practices 100, SEO 100; LCP 2,9 с, TBT 60 мс, CLS 0. Це лабораторні результати цієї збірки, а не вимірювання публічного CDN або польовий INP.

Після повного motion-redesign: усі 24 браузерні тести пройшли. Зіставлення нормалізованого тексту всіх семи HTML-документів із попереднім випуском підтвердило збереження контенту. Локальний мобільний Lighthouse 13 на остаточній статичній збірці з gzip: Performance 90, Accessibility 100, Best Practices 100, SEO 100; FCP 2,6 с, LCP 3,0 с, TBT 100 мс, CLS 0. Це лабораторна перевірка з увімкненими анімаціями, а не вимірювання публічного CDN або гарантія конкретної частоти кадрів на всіх пристроях.

## Безкоштовна пошукова видимість

`src/lib/seo.ts` формує окремі локальні пошукові описи послуг і структуровані дані Physician, Service, WebPage, WebSite та BreadcrumbList. `scripts/prerender.mjs` публікує їх у початковому HTML та додає взаємні мовні посилання в sitemap; `Layout.tsx` синхронізує розмітку при навігації. Кореневий 404 містить noindex і не переспрямовує неіснуючі адреси на головну. Перевірки: `npm run test:pages -- tests/seo.spec.ts`. Статус доступу до Search Console, адреса sitemap й готові дані для профілю лікарки в Maps: [docs/google-visibility.md](docs/google-visibility.md). Індексація та створення Maps-профілю потребують дій у Google-акаунті власника; публікація збірки не підтверджує їх виконання.
